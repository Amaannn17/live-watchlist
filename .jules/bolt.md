## 2024-05-24 - Avoid Redundant Parsing and Unreliable innerHTML Checks in Polling Architecture
**Learning:** In a polling-based application, simply diffing `innerHTML` to avoid redundant DOM updates is unreliable. Browsers often normalize the assigned HTML string (e.g., reordering attributes or normalizing whitespace/quotes), so reading `innerHTML` back might yield a different string than what was just assigned. This leads to false positives in the diff and triggers unnecessary DOM re-renders on every tick.
**Action:** Always cache the raw, unparsed response using `response.text()` first to short-circuit processing on unchanged polling data. For necessary dynamic DOM updates, cache the generated string in a custom property (e.g., `_rawHtml`) on the DOM node to act as the source of truth for diffing, bypassing browser normalization artifacts.

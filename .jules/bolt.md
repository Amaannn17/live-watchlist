## 2024-05-24 - [Avoid `innerHTML` string equality checks for DOM updates during polling]
**Learning:** Checking `element.innerHTML !== newHTMLString` is highly unreliable and expensive because the browser normalizes HTML when it's injected (e.g., adding closing tags, changing attribute quoting, or standardizing whitespace). In an app with frequent polling, this causes `innerHTML` checks to fail even when the raw data hasn't changed, leading to unnecessary DOM updates, layout thrashing, and high CPU usage.
**Action:** Instead of reading from `element.innerHTML` to compare state, store the generated raw HTML string on a custom DOM node property (e.g., `element._rawHtml = newHTMLString`) and compare against that cache before re-rendering (`if (element._rawHtml !== newHTMLString)`). This guarantees exact string matching and prevents redundant DOM writes.
